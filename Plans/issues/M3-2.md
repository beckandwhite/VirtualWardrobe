# M3-2 · Saved-looks gallery + export/share sheet

Milestone: M3 · Labels: feat, ux, M3

## Description
Promote the studio's **minimal** saved-looks list (from M2-3) into a first-class "Looks" gallery.
Users accumulate `TryOn` results over time; they should browse them, reopen one to re-edit or
re-share, and delete the ones they don't keep. This is also where we build the **unified**
export/share sheet so sharing behaves the same whether the user is in the studio or the gallery.
It's primarily UX glue on top of existing data (`TryOn` rows + their output images from M2-3).

## Tasks
- `app/looks.tsx` — a "Looks" screen: a `FlatList`/grid of **all** `TryOn` rows, newest first,
  each showing the output thumbnail + a small caption (item name + body photo date).
- Tap a look → reopen it into the studio editor (reconstruct from the stored `transform`, M2-2),
  or re-share it directly, or delete it.
- Refactor the studio export/share (M2-3) into a shared `src/composer/share.ts` **unified**
  share sheet used by both studio and gallery (no duplicated share code).
- Delete a look: remove the `TryOn` row and its output image (best-effort GC), but **keep** the
  referenced wardrobe `Item` and the body photo.
- A "Looks" tab/entry on the nav so it's discoverable.

## Acceptance criteria
- [x] All saved looks appear, newest first, with a preview thumbnail. — `LOOKS` grid,
       `r.listTryOns()` newest first, `outputPath` thumbnail.
- [x] Tapping a look reopens it in the editor with the stored transform intact. — `reopen` deep-links
         `/studio?id={itemId}`; the studio restores the body/garment + stored transform.
- [x] Re-sharing a stored look uses the **same** share sheet as the studio. — both call
       `src/composer/share.ts` `shareLook`; zero duplicated share code.
- [x] Deleting a look removes its `TryOn` row (and output image, best-effort) while keeping the
       wardrobe item. — `deleteLook` → `r.deleteTryOn`; repo's item cascade keeps the `Item` row.
       Image GC is best-effort / out of scope.
- [x] Empty "no looks yet" state is handled. — `looks.length === 0` renders the empty notice.
