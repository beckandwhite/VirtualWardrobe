# M1-3 · Gallery grid + filter/search

Milestone: M1 · Labels: feat, ux, M1

## Description
The wardrobe browse experience: a responsive grid of thumbnails with filter-by-category and
filter-by-color, plus free-text search over name and tags. This is where the user spends most
of their time before try-on, so it needs to feel snappy: a virtualized, paginated list, memoized
filter logic, and a clear empty state. It also seeds the try-on experience with a one-tap
**"Try on"** deep-link that preselects the chosen item in the studio (M2-2 / M2-4).

Filtering and search are pure functions over the in-memory store snapshot, which keeps the UI
re-render cheap and makes the logic unit-testable in `tests/` (alongside the transform math).

## Tasks
- `app/(wardrobe)/index.tsx` — `FlatList`/`SectionList` grid (column-width based on screen size)
  of `Item` rows, each a thumbnail + caption.
- `src/wardrobe/filter.ts` — pure `filterItems(items, {category, color})` and
  `searchItems(items, query)` (case-insensitive over `name` + `tags`); export and unit-test them.
- A filter/search bar row: category chips, a color swatch row, and a text field; combine active
  filters with AND semantics.
- Reuse `useItems()` from M1-2; derive the visible list with `useMemo` keyed on the query/filters.
- Long-press / tap → `item.tsx` detail (M1-2); a "Try on" button/press that navigates via Expo
  Router to the studio with the item id as a route param (e.g. `router.push('/studio?item=<id>')`).
- Empty state: a friendly illustration + a "Add an item" CTA when zero items match.

## Acceptance criteria
- [ ] Grid virtualizes: scrolls smoothly with 50+ items on web and simulator.
- [ ] Each filter returns the correct subset; multiple active filters AND together.
- [ ] Search matches `name` **and** `tags`, case-insensitively.
- [ ] Clearing all filters/search shows the full wardrobe again.
- [ ] Empty state renders (no rows) and offers the add CTA.
- [ ] "Try on" deep-links to the studio with that item preselected.
- [ ] `filter.ts` / `searchItems` have passing Jest tests.

## Deps
Depends on M1-2.

## Out of scope
- Server-backed search / faceted index — not in MVP (search is in-memory; local-only per ADR-004).
- Saved filter "views" / sorting preferences — deferred.
