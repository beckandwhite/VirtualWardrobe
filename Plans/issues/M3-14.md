# M3-14 · Storyboard the core wardrobe-to-try-on user journey

Milestone: M3 · Labels: ux, docs, M3

## Autonomous-subagent brief

Execute this product-planning issue autonomously. You may choose reasonable defaults for unresolved
UX questions; log every material decision in `Plans/decision-log.md` and continue without waiting
for approval. Do not implement follow-up features in this issue.

## Description
Run a focused product-planning session to storyboard the core VirtualWardrobe journey and
translate it into a small, coherent set of application pages. The goal is to make the next UX
and implementation decisions explicit before adding more surface area to the app.

The session should start with the user's intent to build a wardrobe, move through adding or
selecting an item, creating a try-on, reviewing the result, and saving or sharing a look. It
should also identify the important empty, permission, error, and return-user states without
turning this item into an implementation task.

## Tasks
- Define the primary user journey from first launch or an empty wardrobe through capture/catalog,
  try-on, review, and saved looks.
- Create a storyboard with a few representative frames/pages, including the purpose, primary
  action, and next transition for each page.
- Translate the storyboard into a page map covering the existing surfaces (onboarding, wardrobe/
  catalog, capture, studio, and looks) and any genuinely missing page or modal.
- Mark which steps are required for the happy path versus follow-up or optional flows.
- Record unresolved product and UX decisions, including navigation, back behavior, permissions,
  empty states, and what happens after saving or sharing.
- Attach or link the resulting storyboard and update the relevant architecture/product notes so
  implementation work can reference it.

## Acceptance criteria
- [ ] A written primary user journey exists from first launch or empty wardrobe to a saved or
      shared look.
- [ ] The storyboard contains a small set of page-level frames, and every frame names its user
      goal, primary action, and next transition.
- [ ] The page map clearly identifies which existing app route owns each step and calls out any
      new route or modal that is actually needed.
- [ ] At least the empty wardrobe, camera permission or capture failure, no-result try-on, and
      returning-user paths are addressed.
- [ ] Open UX/product decisions are recorded with an owner or a next decision point;
      implementation tasks are not silently invented in this planning item.
- [ ] The artifact is linked from the relevant local planning documentation and is ready to
      decompose into follow-up work items.
