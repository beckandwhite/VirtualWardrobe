# M3-1 · [spike] EAS prebuild + MediaPipe/Tasks pose for native

Milestone: M3 · Labels: spike, ml, M3

## Description
**Non-blocking spike.** The whole project's #1 risk: can we bring **on-device pose** to native
(iOS/Android) behind the existing `PoseProvider` interface, so web and native finally share one
implementation instead of native running the manual fallback forever? We do **not** block the MVP
on this — the manual overlay (M2-4) is the shipping path until and unless this spike comes back
go. The spike's deliverable is a decision, not a feature.

The blocker is that Expo **Go** cannot run custom native code, so on-device ML requires an EAS
**prebuilt/preview** build. That prebuild + a learning curve is exactly why ADR-005 pushes native
pose to a spike and ships web pose for the demo.

## Tasks
- Create an EAS **prebuilt** dev/preview client (`eas build --profile preview`) so native custom
  code can run (Expo Go can't).
- Integrate on-device pose: either `@mediapipe/tasks-vision` (`PoseLandmarker`) via a prebuild
  dependency, or `react-native-vision-camera` + an on-device model; pick whichever has the
  smoothest native integration for the chosen SDK.
- `src/pose/MediaPipePoseProvider.ts` — `implements PoseProvider` returning the **same** normalized
  `Keypoint[]` shape as `MoveNetPoseProvider` (M2-1), feeding `computeGarmentBox` unchanged.
- Run it on a real device (or a real-device emulator with a camera) and time the first inference.
- Write the **go / no-go** conclusion; if go, add a short ADR noting the native pose path; if no-go,
  record the reasons and confirm M2-4 stays the native path.

## Acceptance criteria (spike success)
- [ ] A device (prebuilt) build runs on-device pose and returns keypoints.
- [ ] Keypoints feed `computeGarmentBox` **exactly like web** (same type, same coordinates).
- [ ] A written go / no-go conclusion is attached (DoD for `spike`); an ADR is added if it changes
      the plan.
- [ ] If no-go: documented reasons + confirmation the manual fallback (M2-4) remains the native
      path, with the UI untouched.

## Notes
The #1 risk in the whole project. Kept as a spike so it never blocks the MVP. Do not let a
struggling spike stall M1/M2 — the manual fallback is always a complete, shippable experience.

## Deps
Depends on M2-1 (web provider as the reference impl) and M2-2. Non-blocking for MVP.
