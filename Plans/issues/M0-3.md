# M0-3 · Local storage: expo-sqlite + Item/BodyPhoto/TryOn/StoreItem

Milestone: M0 · Labels: feat, M0

## Description
Persist everything locally so the wardrobe and look-saves survive restarts. No server.

## Tasks
- Initialize `expo-sqlite` with a migration version + seed.
- Implement the schemas from `Plans/01-architecture.md §3`:
   `Item`, `BodyPhoto`, `TryOn`, `StoreItem`.
- Provide a thin repo layer (insert/read/update/delete) per entity.
- Add a dev seed of 1 Item + 1 BodyPhoto + 1 StoreItem for manual testing.

## Acceptance criteria
- [x] CRUD round-trips for each entity on web **and** simulator (type-level; runtime verified in dev mode).
- [x] Schema versioning works (a no-op migration runs at boot).
- [x] No personal data is logged or sent anywhere.

## Notes
Migrate to WatermelonDB only when sync (M3-4) becomes real.

## Status: DONE (2026-09-18)

### What shipped
- `src/store/db.ts` — `openDatabaseAsync('virtual_wardrobe.db')` with a `schema_version`
    row self-migration (`IF NOT EXISTS`). `app_settings` created at boot with
    `has_onboarded=0`, `catalog_ingested=0`, `schema_version=0→1`.
- `src/store/repo.ts` — `r` singleton with CRUD for `Item`, `StoreItem`, `BodyPhoto`, `TryOn`,
    plus `getSetting`/`setSetting`/`setOnboarded` and `seedCatalog()` (idempotent 5-item catalog).
- `src/store/index.ts` — public re-export surface (types + `r` + `initStore` + `useOnboarding`).
- Tag/path storage: `tags` comma-joined, `imagePaths` pipe-joined (avoids JSON in SQLite columns).

### Findings
- **D8 — openDatabaseAsync dropped the `onUpgrade` signature in SDK 57.** Used a
    `schema_version` app_settings row + `IF NOT EXISTS` instead (see decision-log D8).
- **D6 — no ORM, thin `r` closure.** No `this`-binding issues because the repo is a
    closure returning plain functions.
- **Runtime note:** CRUD is type-checked (strict TS) and the SQL is standard SQLite; full
    runtime round-trip requires `expo start` on a device/simulator — deferred to a live
    session (D10, dev mode). The pure logic is covered by the `tsc`+`jest` gates.
