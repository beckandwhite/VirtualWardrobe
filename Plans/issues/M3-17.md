# M3-17 - [autonomous] Improve application navigation and return paths

Milestone: M3 · Labels: feat, ux, M3

## Autonomous-subagent brief

Execute this issue autonomously. Routine routing and interaction decisions are allowed. For
material product, route ownership, back behavior, or scope decisions, choose the lowest-risk
option consistent with M3-14 and existing ADRs, log the decision in `Plans/decision-log.md`, and
continue without waiting for approval. Finish as `DONE`, `PARTIAL`, or `NO-GO`; do not commit or
open a pull request.

## Goal
Make movement through the application predictable: users should understand where they are, reach
the primary wardrobe, catalog, studio, and looks surfaces, and return from capture, studio, and
sharing without losing context or creating duplicate screens.

## Scope
This issue improves the existing Expo Router structure and navigation behavior. It does not add
new product capabilities, redesign the storyboard, or replace the existing local store.

## Tasks
- Use the M3-14 page map as the route ownership source of truth and document any route mismatch
  before changing it.
- Audit the current tab, modal, and deep-link routes, including wardrobe, catalog, looks, capture,
  studio, onboarding, and item detail.
- Define and implement predictable behavior for tab switching, back navigation, cancel actions,
  save/share completion, permission denial, invalid item IDs, and returning to the originating
  surface.
- Preserve useful context when entering studio or capture, and prevent duplicate route pushes when
  a user repeats the same action.
- Make active-tab, screen titles, and primary navigation controls accessible and consistent with
  the existing design language.
- Add focused route/navigation tests for the happy path and the most important error/return paths.

## Acceptance criteria
- [ ] Every current user-facing route has one documented owner and an intentional entry/exit path.
- [ ] Wardrobe, catalog, looks, capture, studio, onboarding, and item detail are reachable from
      the intended places without dead ends or accidental duplicate stacks.
- [ ] Back, cancel, save, share, permission-denied, invalid-item, and returning-user paths have
      deterministic behavior and preserve or intentionally reset context.
- [ ] The active navigation state and screen titles communicate the current location and remain
      usable at narrow and wide viewports.
- [ ] Deep links continue to resolve using the canonical parameters and do not bypass required
      onboarding or state checks.
- [ ] Focused navigation tests, typecheck, and lint pass; material decisions are logged in
      `Plans/decision-log.md`.

## Dependencies
M3-14 is the source of truth for the page map and product journey. Builds on the existing M1/M2
Expo Router structure. M3-16 may add a welcome entry state; coordinate route ownership without
making the welcome screen a prerequisite for all navigation tests.
