# M1-2 · Item CRUD + thumbnail gen

Milestone: M1 · Labels: feat, M1

## Description
Turn a captured `Item` draft (M1-1) into a first-class wardrobe item and give the user full
create/read/update/delete over those items. The headline UX win here is **fast thumbnails**:
a full-resolution garment photo is stored once, and a small thumbnail is generated so the
gallery (M1-3) never has to decode megabytes on scroll. This issue also owns the **detail/edit
screen** where the item is typed (category, color, tags) and where a user can correct a capture.

All reads/writes go through the `expo-sqlite` repo layer from M0-3, so the UI stays stateless
with respect to persistence. Delete must be safe: removing an item should also remove any `TryOn`
rows that reference it (orphan rows would break the saved-looks gallery in M3-2).

## Tasks
- `src/store/useItem.ts` — hooks over the M0-3 repo: `useItems()`, `useItem(id)`, `upsertItem`,
  `deleteItem`. Keep them synchronous-from-the-UI's view (await the repo, then refresh state).
- `app/(wardrobe)/item.tsx` — detail/edit screen: preview image, type selector
  (`top|bottom|dress|outerwear|shoes|other`), color picker (small swatch set), tag input
  (comma/enter → `tags[]`), and Save/Delete.
- `expo-image-manipulator` `Manipulator` to generate a 400×400 (or device-scaled) thumbnail and
  write its path to `Item.thumbnailPath`; keep the full-res image in `path`.
- Optional: a simple auto-trim / "garment cutout" attempt via `Manipulator` crop around the
  center; ship a **manual crop** fallback and never block on a perfect cutout (ADR-001 keeps the
  garment as a 2D overlay, not a true cutout).
- Delete an item: cascade-delete related `TryOn` rows first, then the `Item`, then its images
  via `expo-file-system` (best-effort GC; a leftover file is acceptable for MVP).

## Acceptance criteria
- [ ] Add an item with type/color/tags and it appears in the gallery after restart.
- [ ] Edit updates the stored row in place (no duplicate rows).
- [ ] Delete removes the item and any `TryOn` rows that reference it.
- [ ] A thumbnail (not the full image) is what the gallery decodes; thumbnails load fast on a
      long list.
- [ ] Manual crop is usable when auto-trim is unavailable; no crash on either path.
- [ ] No orphaned images blow up storage; a GC pass is best-effort and documented.

## Deps
Depends on M1-1.

## Out of scope
- True alpha-matte / background removal (segmentation) — deferred; the overlay is a 2D box.
- Tag auto-suggestion / sync — not in MVP.
