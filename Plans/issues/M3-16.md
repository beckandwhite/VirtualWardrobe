# M3-16 - [autonomous] Welcome screen: explain VirtualWardrobe and the try-on flow

Milestone: M3 · Labels: feat, ux, M3

## Autonomous-subagent brief

Execute this issue autonomously. Routine UI and copy decisions are allowed. For material product,
accessibility, scope, or navigation decisions, choose the lowest-risk option consistent with the
M3-14 journey and existing ADRs, log the decision in `Plans/decision-log.md`, and continue without
waiting for approval. Finish as `DONE`, `PARTIAL`, or `NO-GO`; do not commit or open a pull request.

## Goal
Add a concise welcome experience that tells a new user what VirtualWardrobe is, how the workflow
works, and what the user can do next. It should orient without becoming a marketing landing page
or blocking a returning user.

## Product message
The welcome screen should communicate this simple model:

1. Add a garment by taking a photo or choosing one from the library.
2. Select a garment and a body photo in the try-on studio.
3. Adjust the result manually when automatic placement is unavailable.
4. Save or share the resulting look.

Use the existing product vocabulary and explain the manual fallback honestly. Do not promise native
ML pose support while M3-1 remains NO-GO.

## Tasks
- Add a first-run welcome screen or welcome state using the existing Expo Router and i18n
  boundaries; do not add a second navigation system.
- Present the four-step workflow with accessible headings, concise supporting copy, and a clear
  primary action into onboarding or the wardrobe flow.
- Provide a skip/continue path and ensure a returning user is not shown the first-run welcome on
  every launch; persist the smallest suitable setting through the existing store.
- Cover loading, empty, permission-denied, and unavailable-image states without inventing new
  feature behavior.
- Add focused tests for first-run persistence, primary-action routing, skip behavior, and the
  manual-fallback wording.
- Put all user-visible copy in the canonical i18n catalog; do not expand locale count here.

## Acceptance criteria
- [ ] A new user sees what the app is, how garments enter the wardrobe, how try-on works, and how
      looks are saved/shared before entering the main flow.
- [ ] The primary action reaches the intended onboarding/wardrobe entry route and skip/continue
      behavior is deterministic.
- [ ] A completed welcome state is persisted and returning users are not repeatedly interrupted.
- [ ] Copy accurately describes manual fallback and does not claim unavailable native pose support.
- [ ] Accessibility labels, focus/order behavior, and readable layout are covered on narrow and
      wide viewports.
- [ ] Tests, typecheck, and lint pass; material decisions are logged in the main decision log.

be required to implement the welcome copy and persistence.
