# M1-1 · Camera + library capture

Milestone: M1 · Labels: feat, M1

## Description
This is the entry point of the wardrobe vertical slice: users get items into the app by
either photographing a garment or importing an existing photo. It produces an **`Item` draft**
(a persisted row with a stored image but no finalized metadata yet), which M1-2 turns into a
fully typed wardrobe item. Keeping it a "draft" decouples *getting an image in* from *typing it*,
so capture stays frictionless and the studio (M2) can start from either source.

Capture needs to work on **all three targets**, which is the tricky part: native uses a real
camera + photo picker, while web has no `expo-camera` and falls back to a file input. We centralize
that behind a single hook so the screens never branch on platform.

## Tasks
- **Routing baseline (D19.4):** restructure `app/_layout.tsx` to a **tab layout** — 3 tabs
   [Wardrobe `(wardrobe)/index`, `catalog`, `looks`]; studio stays flat (`app/studio.tsx`, a modal).
  This baseline lands here so the M1-1 capture screen and the M1-2/M1-3 wardrobe screens slot into the
   `(wardrobe)` group coherently.
- **Draft = `type='other'` + default color, no migration (D19.5):** the `items` table has no
  draft/status column, so a captured draft is an `Item` row with `type='other'` until M1-2 types it.
- Add `expo-camera` (native) and `expo-image-picker` (all platforms) to the project.
- `src/capture/useCapture.ts` — a platform-agnostic hook that wraps
  `ImagePicker.launchCameraAsync` / `ImagePicker.launchImageLibraryAsync` and, on web, an
  `<input type="file" accept="image/*" capture>` element. Returns `{ photo, source, takePhoto }`.
- Persist the captured image with `expo-file-system` to a stable path under the app's docs dir,
  and create an `Item` draft row via the store layer (M0-3) with `thumbnailPath = fullPath`
  and a null/`'other'` type until typed.
- `app/(wardrobe)/capture.tsx` — capture screen with a big "Photo" / "Camera" FAB; on import,
  push to the draft edit screen (M1-2).
- Best-effort garment-type hint: a tiny heuristic (user picks top/bottom/dress/… via a quick
  chip row) rather than a model; the hint pre-fills the draft but is not required.
- Guard the camera path with the permission result from M0-4; if camera is denied/unavailable,
  hide the "Camera" action and keep "Library" usable.

## Acceptance criteria
- [ ] "Library" produces a stored image + an `Item` draft row on web and simulator.
- [ ] "Camera" produces a stored image + an `Item` draft row on a simulator/emulator and iOS.
- [ ] On web, the file input accepts a chosen image and creates a draft (no crash).
- [ ] Draft row is retrievable from the store after a full app restart.
- [ ] When camera is unavailable/denied, only the "Library" flow is shown and nothing crashes.
- [ ] No personal data is uploaded; the image stays on-device (ADR-004).

## Deps
Depends on M0-3 (storage) and M0-4 (permissions).

## Out of scope
- Garment-type **classification via ML** — deferred; the heuristic chip row is enough for MVP.
- Auto-crop / background removal — that belongs to M1-2's thumbnail step.
