# M3-5 · Dev-env: headless-browser harness for the `ml`/`spike` DoD

Milestone: M3 · Labels: debt, tooling, M3

## Problem
M2-1 ("Web MoveNet pose") and M3-1 (native spike) both carry a Definition of Done
that requires a **screenshot of the running UI**, plus a one-run demo note. The
current dev environment can't satisfy this:

- **No browser in the sandbox.** The Expo web build can't be rendered here, so no
  screenshot can be produced — M2-1's `ml` DoD was therefore **waived** this
  session (user-accepted). The studio runs but nobody confirms the visual.
- **The canonical MoveNet source is dead.** `tfhub.dev/google/tfjs-model/movenet/*`
  currently 302-redirects to Kaggle and the old `tfhub-public` GCS bucket is gone,
  so `npm run fetch:pose` may fail. See `docs/dev-setup.md` §2.
- **Native simulator** (iOS/Android) is likewise not runnable in the sandbox.

## Goal
A reproducible, CI-runnable harness that proves the try-on pipeline *visually and
automatically*, without a human clicking through a browser — closing the loop the
sandbox can't.

## Tasks
- Add a `playwright` script (`scripts/pose-smoke.mjs` or a `tests/e2e/` suite)
  that:
  1. Starts the Expo web build (`expo start --web` or a static `web-build/`).
  2. Drives a Chromium/WebKit instance to the `/studio` route.
  3. Loads a fixed body-photo fixture + a catalog garment.
  4. Waits for `MoveNet` to auto-place (or, when the model isn't fetched, for the
    manual fallback banner to render — assert on the status text).
  5. Captures a PNG → `docs/screenshots/studio-*.png` and asserts on key
    DOM/console signals (no errors thrown; a garment element present).
- Keep it **skippable**: if `MOVENET_MODEL_URL` / the model bytes are absent, the
  test asserts the *manual-fallback* path instead of failing — so CI stays green
  on a clean machine and the model is an enhancement, not a gate (ADR-004: local).
- Wire the harness into the DoD so the screenshot becomes an artifact instead of a
  human task. Document in `docs/dev-setup.md` §7.
- Consider whether the same harness can drive a native Expo Go E2E for the
  simulator DoD (probably out of scope here — call it out as a follow-up).

## Acceptance criteria
- [ ] `npm run e2e:pose` produces a PNG of a completed (auto- or manual-) placed garment.
- [ ] The run is skippable-when-model-absent and still asserts the happy path.
- [ ] A one-run demo note can be auto-generated from the run log + PNG.
- [ ] Documented: a fresh dev box does `npm install && npm run fetch:pose && npm run e2e:pose` and gets a screenshot.

## Notes / why now
- This unblocks M2-1's real DoD and makes M3-1's spike reproducible (a spike's
  "go / no-go" is far more convincing with an attached screenshot than an
  anecdote).
- Playwright is the suggested approach (user guess). `@playwright/test` brings a
  headless browser + assertions; the only integration point is `expo start --web`.
- It's `debt`/`tooling`, not a user feature — it improves *confidence* in `ml`
  work. Land it right after M2-2 lands the auto-box so there's real auto-place to
  assert on.
