# M3-3 · App icons / launch screens / i18n / store asset prep

Milestone: M3 · Labels: feat, ux, M3

## Description
Polish for a **public portfolio release**. The app needs to look and feel finished: a real icon,
a branded splash/launch screen, and a small i18n layer so it's not English-hardcoded. These are
the details that make a side project read as a real product and look right in a store or a
portfolio/demo page. Most is config + asset work on top of the structures stubbed in M0-4
(onboarding) and M1 (i18n-ready strings).

## Tasks
- `app.json` (expo): add `icon`, and per-platform **adaptive** icons (iOS + Android) via
  `expo-icon`/the icon field, plus a custom `splash` configuration (via `expo-splash-screen`) with
  a brand color and image.
- i18n: wire the M0-4 string structure to a real library (e.g. `i18next` + `react-i18next`) and
  add at least **2 locales** (e.g. en + one more) with a language switch in settings; verify a
  switch does not crash-reload the app.
- Store/portfolio asset kit: a set of **screenshots** (onboarding, gallery, studio, a shared look)
  and a short read-me describing the demo path for a portfolio page.

## Acceptance criteria
- [~] App builds and launches with custom icons + a branded splash on **both** iOS and Android.
      — config in place (`app.json` `splash` + `icon`), **device-build not verifiable in-sandbox**.
- [x] The app at least partially supports 2 locales and a language switch works without a
      reload-crash. — en + es catalog; `LanguageSwitcher` re-renders via context (no reload).
- [ ] A screenshots set (gallery/studio/share at minimum) exists for a store/portfolio page.
      — **out of scope in-sandbox** (needs a rendered run; pairs with M3-5 `e2e:pose`).
- [~] No leftover placeholder/placeholder icon or default Expo splash in a release build. —
      branded `splash` + `icon` set, but "release build" not produced in-sandbox.
