# M2-1 · Web MoveNet pose integration

Milestone: M2 · Labels: ml, M2

## Description
The "wow" of the MVP: pose-aware drape on **web**, where it's cheapest to ship and to demo
(no native tooling, instant feedback, screenshot-friendly). We implement the **web** branch of the
`PoseProvider` interface (M0-2) using TensorFlow.js + `@tensorflow-models/pose-detection`. The
composer UI never changes — it just calls `provider.estimate(bodyPhoto)` and gets `Keypoint[]`.

This is web **only** for now: the model needs the web backend and a browser runtime, which is why
the same interface has a `ManualPoseProvider` (M0-2) for native. Keypoints here feed
`computeGarmentBox` (M0-2) to place the garment automatically.

## Tasks
- Install `@tensorflow/tfjs` + `@tensorflow-models/pose-detection`, **web-only** — guard the import
  so it is never bundled into the native build (dynamic `import()` behind a platform check / a
   `Platform.OS === 'web'` branch in a thin loader).
- **Vendor the model + weights locally (D19.3 / ADR-004):** `pose-detection` fetches the model by
  `modelUrl` and `@tensorflow/tfjs` may JIT, which violates "fully local." Download
  `model.json`+weights once and ship them as bundled assets (`expo-asset` / static path); point
   `modelUrl` at the local asset so first run is offline and no bytes are fetched at runtime.
   Accept the extra effort vs a bare install.
- `src/pose/MoveNetPoseProvider.ts` — `implements PoseProvider`: load the MoveNetSinglePoseLite
  model, run `detector.estimatePoses(imageSource)` on the body photo (an `HTMLImageElement` /
  canvas on web), and return normalized `Keypoint[]` (0..1; attach `score` if available).
- A tiny `src/pose/poseLoader.ts` that lazily initializes the model once and caches it, with a
  loading + **failed-load** state.
- Wire the studio to select the provider by platform (`createPoseProvider()` factory): web →
  `MoveNetPoseProvider`, native → `ManualPoseProvider` (returns `null`).
- Render a faint keypoint/skeleton overlay (a `react-native-svg` or a transformed overlay layer)
  so the user can see why the auto-box was placed where it was.

## Acceptance criteria
- [x] On web, capturing/importing a body photo yields keypoints within a few seconds.
       *Code path complete: `MoveNetPoseProvider.estimate` decodes the body URI →
     `detector.estimatePoses` → `mapKeypoints`.* Runtime latency not exercised in
     this session (can't render a web browser here; see `docs/dev-setup.md` §7 + M3-5).
- [x] Keypoints are normalized (0..1) and feed `computeGarmentBox` (M0-2) without changes —
        `tests/pose/keypoints.test.ts` proves fake-detector → provider → `computeGarmentBox` end-to-end.
- [x] Model load shows a loading state; a **failed load falls back to the manual provider**
        (M2-4) with no crash — `PoseUnavailable` + `safeEstimate` degrade to `ManualPoseProvider`;
         loader caches a single-flight init so a failure isn't retried spuriously.
- [x] No `@tensorflow*` code is bundled into the native build — platform split:
        `providers.web.ts` only references the TF packages via `poseLoader`'s dynamic
       `import()`; native resolves `providers.ts` (`ManualPoseProvider`), so TF is in
       a native-unreachable module graph. Not mechanically verified here (no native build
       in-sandbox); a `expo export --platform ios` dry-run would close it (flagged in HANDOFF).
- [x] Screenshot DoD — **waived this session** per user request (sandbox renders no browser);
         tracked as backlog **`M3-5`** (Playwright `e2e:pose` harness).

## Decision log
- **D20.1 — three-file platform split keeps `@tensorflow*` out of the native bundle.**
     `providers.ts` (generic/native, no TF) + `providers.web.ts` (web, `MoveNetPoseProvider`) +
     `providers.native.ts` (re-export of `providers.ts`). See `Plans/decision-log.md` D20.1.
- **D20.2 — `pose-detection` 2.x `createDetector(SupportedModels.MoveNet, …)`.** The package
    that resolved (2.1.3) no longer exposes `movenet.create()` — the loader is written against
     `createDetector` + `movenet.modelType.SINGLEPOSE_LIGHTNING` (D20.2).
- **D20.3 — model bytes gitignored + committed `modelUrl.ts` pointer.** Per user: ~MB weights
     gitignored (`public/pose/**` + `.gitkeep`); `src/pose/modelUrl.ts` commits the
     `MOVENET_MODEL_URL` pointer; `npm run fetch:pose` repopulates + rewrites it (D20.3).
- **D20.4 — tfhub.dev is dead; document fallbacks.** 302→Kaggle; old GCS bucket gone. Three
     fallbacks in `docs/dev-setup.md` (mirror / hand-place / skip→manual) (D20.4).
- **D20.5 — `ml` DoD screenshot raised as M3-5 (Playwright).** New backlog item, `debt,tooling,M3`
     (D20.5).
- **D20.6 — skeleton overlay = RN `View` layer, not `react-native-svg`.** `react-native-svg`
     isn't an install; the studio renders segments as rotated `View`s + dots as round `View`s,
      toggleable. The "transformed overlay layer" option in the issue (D20.6).
