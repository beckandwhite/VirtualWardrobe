# M2-1 · Web MoveNet pose integration

Milestone: M2 · Labels: ml, M2

## Description
The "wow" of the MVP: pose-aware drape on **web**, where it's cheapest to ship and to demo
(no native tooling, instant feedback, screenshot-friendly). We implement the **web** branch of the
`PoseProvider` interface (M0-2) using TensorFlow.js + `@tensorflow-models/pose-detection`. The
composer UI never changes — it just calls `provider.estimate(bodyPhoto)` and gets `Keypoint[]`.

This is web **only** for now: the model needs the web backend and a browser runtime, which is why
the same interface has a `ManualPoseProvider` (M0-2) for native. Keypoints here feed
`computeGarmentBox` (M0-2) to place the garment automatically.

## Tasks
- Install `@tensorflow/tfjs` + `@tensorflow-models/pose-detection`, **web-only** — guard the import
  so it is never bundled into the native build (dynamic `import()` behind a platform check / a
   `Platform.OS === 'web'` branch in a thin loader).
- **Vendor the model + weights locally (D19.3 / ADR-004):** `pose-detection` fetches the model by
  `modelUrl` and `@tensorflow/tfjs` may JIT, which violates "fully local." Download
  `model.json`+weights once and ship them as bundled assets (`expo-asset` / static path); point
   `modelUrl` at the local asset so first run is offline and no bytes are fetched at runtime.
   Accept the extra effort vs a bare install.
- `src/pose/MoveNetPoseProvider.ts` — `implements PoseProvider`: load the MoveNetSinglePoseLite
  model, run `detector.estimatePoses(imageSource)` on the body photo (an `HTMLImageElement` /
  canvas on web), and return normalized `Keypoint[]` (0..1; attach `score` if available).
- A tiny `src/pose/poseLoader.ts` that lazily initializes the model once and caches it, with a
  loading + **failed-load** state.
- Wire the studio to select the provider by platform (`createPoseProvider()` factory): web →
  `MoveNetPoseProvider`, native → `ManualPoseProvider` (returns `null`).
- Render a faint keypoint/skeleton overlay (a `react-native-svg` or a transformed overlay layer)
  so the user can see why the auto-box was placed where it was.

## Acceptance criteria
- [ ] On web, capturing/importing a body photo yields keypoints within a few seconds.
- [ ] Keypoints are normalized (0..1) and feed `computeGarmentBox` (M0-2) without changes.
- [ ] Model load shows a loading state; a **failed load falls back to the manual provider**
      (M2-4) with no crash.
- [ ] No `@tensorflow*` code is bundled into the native build (verify native bundle size / no
      unresolved native dep).
- [ ] Attach a screenshot + a one-run demo note to this issue (DoD for `ml`).

## Notes
Web-only for now. Native on-device pose is the M3-1 spike; the `PoseProvider` abstraction exists
precisely so that drops in behind the same UI. If MoveNet proves unsatisfactory, a documented
no-go just keeps the manual fallback as the native path — the UI is untouched.

**M0 handoff (from M0-1, D9):** `babel.config.js` currently omits the
`react-native-reanimated/plugin` because it fails the web Metro bundler while unused.
**When M2-2 adds drag/scale with Reanimated, re-enable it in `babel.config.js` and verify the
web export unblocks.** Native builds already have `react-native-worklets` installed (D12).

## Deps
Depends on M0-2 (interfaces). **Independent of M1** (does not need M1's image work) and may proceed
 in parallel with M1 (D19.2). Feeds M2-2 (auto-box + fine-tune).
