## Problem
The canonical TFJS MoveNet graph is dead everywhere public (see M3-1 / D21 / `docs/dev-setup.md`
§2): `tfhub.dev` 302-redirects to Kaggle, the `tfhub-public` GCS bucket is gone, and
`@tensorflow-models/pose-detection` hardcodes the dead `tfhub.dev/.../movenet/singlepose/lightning/4`
URL. `npm run fetch:pose` therefore fails and `public/pose/movenet-singlepose-lite/` is empty
(a stale Kaggle-HTML `model.json` was left there and must be deleted first).

But a **live ONNX copy** of the *same* model exists:
`https://huggingface.co/Xenova/movenet-singlepose-lightning/resolve/main/onnx/model.onnx`
(≈9.4 MB, HTTP 200). `@tensorflow-models/pose-detection` needs a **TFJS graph**, not ONNX, so
this work item converts the ONNX asset locally into a TFJS graph and drops it into the repo.
This is the user's "start-first" path: it's the quickest route to a *real* model without
waiting on a human to hand-deliver one (that's M3-7).

## Competition rule

M3-6 and M3-7 are mutually substitutable paths. Whichever produces the first independently
verified, network-free graph wins the shared `public/pose/` slot. Record the comparison and close
the other issue as superseded; do not maintain two production graphs.

## Goal
Produce a valid **TFJS graph** `model.json` + weights under

`estimatePoses` runs on a fixture image end-to-end.

## Tasks
1. Fetch the ONNX graph to a scratch dir: `curl -fL -o /tmp/mov.onnx
   https://huggingface.co/Xenova/movenet-singlepose-lightning/resolve/main/onnx/model.onnx`.
2. Convert ONNX→TFJS graph:
   `python -m tensorflowjs_converter --input_format=onnx --output_format=tfjs_graph --saved_model_dir /tmp/movjs /tmp/mov.onnx /tmp/movjs/model.json`
   (verify the converter op-coverage; if it warns about unsupported ops, log them — see
   Risk). Inspect the emitted `model.json` `weightsManifest` for its binary paths + `sha256`.
3. Place the graph: copy `model.json` + the `group1-shard*.bin` files into
   `public/pose/movenet-singlepose-lite/` and `assets/pose/movenet-singlepose-lite/`
   (keep `.gitkeep`, gitignored per `docs/dev-setup.md` §1).
4. Regenerate the loader pointer: `node scripts/fetch-movenet.mjs --emit-url-only`
   (writes `src/pose/modelUrl.ts` → `/pose/movenet-singlepose-lite/model.json`).
5. Prove it: run the M3-5 harness `npm run e2e:pose` (now that the model is present the browser
   pass can fire if `@playwright/test` is installable) **or** a minimal node/TFJS sanity call
   that loads `MOVENET_MODEL_URL` and runs `estimatePoses` on a bundled sample body photo, then
   assert ≤17 COCO keypoints come back. Prefer the existing `scripts/pose-smoke*.mjs` over new code.
6. Run the gate: `npx tsc --noEmit`, `npx eslint . --max-warnings 0`, `npm test`. All green.

## Risk
- The ONNX→TFJS converter may not reproduce the exact op set `pose-detection` expects
  (e.g. `NonMaxSuppressionV3`, `SpaceToDepth`, `DepthToSpace`, or `ResizeNearestNeighbor`).
  If the emitted graph throws at `tf.graphModel.load`, that's a **NO-GO for M3-6** — record
  the offending op + converter version and recommend M3-7 (human-supplied, known-good TFJS
  graph) as the reliable path. A NO-GO here is *expected* and *valuable*, not a failure.
