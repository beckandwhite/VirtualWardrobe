# M0-5 · Studio route + pose→garment demo

Milestone: M0 · Labels: feat, ux, ml, M0

## Description
Wire the M0-2 pieces into a visible "wow": a `studio` route that loads a body photo,
runs the `PoseProvider` (manual in M0, since M2-1 adds web MoveNet), places an auto-scaled
garment via `computeGarmentBox`, and lets the user fine-tune with a transform editor. No
Reanimated yet — the editor is a simple absolute-positioned `View` driven by state. Export is
stamped to a path but rendering the composite is M2-3. This milestone proves the full pipeline
pose → box → transform → composed view on screen, all with the manual fallback so it runs today.

## Tasks
- `app/studio.tsx`:
    - A screen that pulls a chosen body photo (`expo-image-picker` import) and a chosen
     wardrobe `Item` (via router param `?id=` or a picker list), defaulting to a bundled
     catalog item if none.
   - Calls `safeEstimate(provider, bodyPhotoUri)` (M0-2) for keypoints; if empty/failed,
    show the "adjusting manually" affordance and start from `IDENTITY_TRANSFORM`.
   - If keypoints present: `computeGarmentBox(keypoints, item.type)` → initial `Transform`
    (M0-2 autoBox), else `IDENTITY_TRANSFORM`.
   - Render the body image full-screen with the garment image overlaid, positioned/scaled by
    `Transform` as a `View` with `transform: [{translateX},{translateY},{scale},{rotate}]`.
   - A minimal manual editor: a `TextInput`/slider row for x, y, scale, rotation, opacity
    (state-driven, no Reanimated). "Reset" → recomputes from pose.
- `createPoseProvider()` factory in `src/pose/index.ts`: web → (M2-1 later), native →
     `ManualPoseProvider`. For M0-5, returns `ManualPoseProvider` everywhere (no TFJS yet).
- Persist the composed result via `r.insertTryOn(bodyPhotoId, itemId, serializeTransform(t))`
     on save; `serializeTransform`/`deserializeTransform` from M0-2.
- Deep-link in: `wardrobe.tsx` "Try on" → `/studio?id=<itemId>`; `looks.tsx` open → `/studio`.

## Acceptance criteria
- [ ] On web + simulator, opening `/studio` shows a body photo with a garment layer that moves
     when the transform inputs change.
- [ ] No keypoint path (manual fallback) starts from a sensible `IDENTITY_TRANSFORM` and never
     crashes.
- [ ] "Save" writes a `TryOn` row; it appears in `/looks`.
- [ ] No `@tensorflow*` import is bundled (web MoveNet is M2-1).
- [ ] `tsc --noEmit` + `eslint .` + `jest` still green.

## Notes
This is the de-risking "it visibly works" gate before the M1 vertical slice. Keep the editor
primitive by design — M2-2 replaces it with Reanimated drag/pinch + the keypoint overlay
(M2-1). The whole point: the data flow (pose→box→transform→save) is fully exercised today.

## Deps
Depends on M0-2 (PoseProvider + autoBox), M0-3 (store), M0-1 (router). Feeds M1-1 and M2-2.
