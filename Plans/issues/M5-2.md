## Problem
The CI workflow needs a dependable testing stage that exercises the repository's automated checks
and leaves clear results in GitHub Actions. A failing test should block delivery, while the workflow
should preserve enough diagnostics for a developer to understand what failed without reproducing the
run locally first.

## Goal
Add the CI/CD testing steps and reporting needed to make automated validation a required, useful
signal for pushes and pull requests.

M5-1 owns workflow installation, typecheck, lint, and security checks. This issue owns the Jest
execution, coverage, result artifacts, diagnostics, and required-check guidance.

## Tasks
1. Define the CI test job's Jest execution after the M5-1 install/typecheck/lint steps, using the repository's
   existing package scripts.
2. Run tests in a clean dependency installation with the Node version and operating-system matrix
   chosen by M5-1.
3. Collect Jest coverage and publish the coverage summary and machine-readable test results as
   workflow artifacts when the scripts support them.
4. Ensure failed tests fail the job and that test logs remain visible in the Actions run summary.
5. Add a pull-request check name and branch-protection recommendation so the test job is required
   before merging.
6. Document how to rerun the job, download artifacts, and distinguish product failures from CI setup
   failures.
7. Validate the workflow on a representative pull request or recorded local dry run.

## Acceptance criteria
- [ ] Every push and pull request runs the automated test job after a clean install.
- [ ] Typecheck, lint, and Jest failures produce a non-successful workflow result.
- [ ] Test output and coverage artifacts are available from the completed workflow when the run
      reaches the reporting step.
- [ ] The required check name and branch-protection setup are documented.
- [ ] A maintainer can identify the failing test and retrieve its diagnostics from the Actions UI.
- [ ] The final issue records the commands, Node/runner context, artifact names, and any limitations.

## Dependencies
- M5-1: GitHub Actions build and security workflow.
- Existing `package.json` scripts and Jest configuration.

## Out of scope
- Device, simulator, and App Store/Play Store tests.
- Replacing Jest or adding a second test framework.
- Full end-to-end browser coverage, which remains covered by the M3 QA work items.
