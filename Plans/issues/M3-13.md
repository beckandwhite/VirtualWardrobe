## Problem
The iOS test environment has **no setup** and **no proven run**: `docs/dev-setup.md` §7.2 says the
simulator can't run in the sandbox, and M1-1's device-touching AC (camera → Item-draft row on the
simulator/iOS) has only ever been "waived." **This item performs the actual setup on this
MacBook** so the iOS path can be exercised — the *execution* half; M3-12 is the *document*.

Because this host is macOS, iOS is the platform **most likely to actually pass** here (unlike the
Android emulator or headless Chromium, which more often hit the sandbox ceiling).

## Goal
On an Apple-Mac, stand up an iOS test target (Simulator, or a device if signed) and get the app
to run on it enough to verify the device-touching flows (ideally M1-1's camera → Item-draft path,
or at least launch + smoke), then record exactly what's reproducible.

## Host rule

This workspace is Windows. A run here must record the Mac-host mismatch as `PARTIAL` or `NO-GO`,
not claim iOS Simulator success. A future Mac-host agent may execute the setup.

## Preconditions / setup
- Node 22 via nvm: `source ~/.nvm/nvm.sh && nvm use 22` (D2).
- Xcode + a recent **iOS Simulator runtime** (`xcodebuild -showsdks` should list an iOS sim
  runtime). If absent, that's the first blocker to find + record.
- Use M3-12's documented commands as the source of truth; if not written yet, use the canonical
  sequence below and record the delta.

## Tasks
1. Verify/Install the iOS Simulator runtime (`xcrun simctl list runtimes`); if missing, note the
   `xcodebuild` install path. Record the Xcode + runtime versions.
2. Boot a Simulator (`xcrun simctl boot <UDID>` / `simctl open booted`); or attach a signed
   device if available. Record which path ran.
3. Launch the app on it: `npx expo start --ios` (Expo Go on the Simulator) for the baseline.
    Confirm the **manual** pose path renders (native uses `providers.native.ts`, not MoveNet —
   dev-setup §3).
4. Exercise the device-touching AC you can: ideally M1-1's camera → stored image + Item-draft row;
   otherwise a launch + navigation smoke. Capture a screenshot/trace as evidence.
5. If a native custom module were ever needed (out of scope here), the path is an **EAS prebuild**
    — reference M3-1; do not build it here.
6. Confirm M3-12's documented commands match what actually worked; flag any drift.
7. Run the JS gate after any config change: `npx tsc --noEmit`, `npx eslint . --max-warnings 0`,
    `npm test`.
