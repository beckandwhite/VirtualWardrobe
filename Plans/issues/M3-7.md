## Context — why this exists alongside M3-6
M3-6 attempts to **synthesize** a TFJS graph by converting the live ONNX asset
(`Xenova/movenet-singlepose-lightning`) with `tensorflowjs_converter`. That's the fast
shot but uncertain (op-coverage). **This** item (`M3-7`) is the **reliable, long-term**
source: obtain or produce a *known-good* TFJS graph that `@tensorflow-models/pose-detection`
is documented to consume, and wire it in. If M3-6 comes back NO-GO (converter can't
reproduce the op set), M3-7 is the path that lands. They share the same drop-in target and
the same `--emit-url-only` final step, so they are mutually substitutable.

## Problem
`@tensorflow-models/pose-detection@2.1.3` hardcodes a dead `tfhub.dev` URL for
MoveNet singlepose-lite and needs a **TFJS graph** (`model.json` + `weightsManifest`
binaries) it can load. No public mirror serves it in the right format. This item resolves
that by sourcing a **verified-correct** graph rather than hoping a converter matches.

## Competition rule

M3-6 and M3-7 are mutually substitutable paths. Whichever produces the first independently
verified, network-free graph wins the shared `public/pose/` slot. Record the comparison and close
the other issue as superseded; do not maintain two production graphs.

## Tasks (pick the first source that yields a *valid, verified* TFJS graph)
1. **Locate a known-good TFJS graph.** Search, in order, for a TFJS-format MoveNet
   singlepose graph: (a) a teammate's / prior-build vendored copy under any local path or
   cache; (b) a GitHub repo that commits `movenet*/model.json` *with* `group1-shard*.bin`
   (jsDelivr/GH raw that serves both; a `pose-detection` demo repo that vendored it);
   (c) the `@tensorflow/tfjs` demo bundles. For each candidate, fetch `model.json`, confirm
   it parses as TFJS (has `modelTopology`/`graph` + `weightsManifest`), and that the
   manifest binaries 404-free.
2. **Reproduce what `pose-detection` expects.** Cross-check input/output tensor names +
   shapes against `node_modules/@tensorflow-models/pose-detection/dist/movenet/` so the
   graph is API-compatible (not just "a movenet graph").
3. **Place + verify.** Copy the validated `model.json` + shards into
   `public/pose/movenet-singlepose-lite/` and `assets/pose/...` (keep `.gitkeep`), run
   `node scripts/fetch-movenet.mjs --emit-url-only`, then run `npm run e2e:pose` (or a
   minimal TFJS load + `estimatePoses` on a sample photo) and assert ≤17 COCO keypoints.
4. **Gate:** `npx tsc --noEmit`, `npx eslint . --max-warnings 0`, `npm test`. All green.
5. **Record provenance.** In the Decision Log, note the **source URL + sha256** of the
   `model.json` so the vendored bytes are auditable and reproducible.
