## Problem
The Android test environment has **no setup** and **no proven run**: `docs/dev-setup.md` §7.2 says
the simulator can't run in the sandbox, and M1-1's device-touching AC (camera → Item draft row on
a simulator/emulator) has only ever been "waived." **This item performs the actual setup on this
MacBook** so the Android path can be exercised — the *execution* half; M3-10 is the *document*.

## Goal
On this Apple-Mac, stand up an Android test target and get the app to run on it enough to verify
the device-touching flows (ideally M1-1's camera → Item-draft path, or at least launch + smoke),
then record exactly what's reproducible.

## Preconditions / setup
- Node 22 via nvm: `source ~/.nvm/nvm.sh && nvm use 22` (D2).
- Apple Silicon: Android emulators here need the **ARM system image** (no x86 KVM on Apple
  silicon). Prefer an ARM image; note the x86 fallback + speed ceiling.
- Use M3-10's documented commands as the source of truth; if not written yet, use the canonical
  sequence below and record the delta.

## Tasks
1. Install the Android SDK toolchain (`sdkmanager` or the Android Studio CLI) + an **ARM system
   image** system. Record the API level + image tag.
2. Create an Android **Virtual Device** (AVD) and launch it; or drive a USB device if one is
   attached. Record which path ran.
3. Launch the app on it: `npx expo start --android` (Expo Go) for the baseline. Confirm the
   **manual** pose path renders (native uses `providers.native.ts`, not MoveNet — dev-setup §3).
4. Exercise the device-touching AC you can: ideally M1-1's camera → stored image + Item-draft row;
   otherwise a launch + navigation smoke. Capture a screenshot/trace as evidence.
5. If a native custom module were ever needed (out of scope here), the path is an **EAS prebuild**
   — reference M3-1; do not build it here.
6. Confirm M3-10's documented commands match what actually worked; flag any drift.
7. Run the JS gate after any config change: `npx tsc --noEmit`, `npx eslint . --max-warnings 0`,
   `npm test`.

## Acceptance criteria
- [ ] An Android SDK + ARM system image + an AVD (or device) exists on this machine.
- [ ] The app launches on it via `npx expo start --android` (Expo Go baseline), manual path OK.
- [ ] At least one device-touching flow is exercised + captured (M1-1 camera→Item-draft, or a
       launch/navigation smoke as a documented minimum).
- [ ] Decision Log records API level, image tag, AVD/device choice, and the reproducible subset.

## Risk

  in-sandbox ceiling as D20.5 / D21.6 / M3-1. If the emulator can't start here, record

  That NO-GO is *expected and valuable*: it documents precisely why Android is deferred and pins
  the reproducible subset for a machine that *can* run it. Do not leave a broken SDK install.
